## 本轮实现

- 设置新增 `translation-program` 字幕来源，订阅独立翻译程序 v1 命名管道。
- 译答不启动、终止或重新配置独立翻译程序，也不对其译文重复调用翻译服务。
- 主界面显示连接和 AI 状态；断线自动重连，首个快照只恢复显示，不自动生成回答。
- 按原文版本配对译文；较早修订的译文不能拼到最新原文上。
- 实时片段稳定约 700 ms 后，按当前回复模式生成建议；修订更新同一张卡片。
- 每条消息提供“回答这一句 / 重试”；重试限于当前上下文内的消息。
- 原文修改或手动重复请求后，旧请求结果不得覆盖新回答；翻译补全不重复触发回复。
- 余额／额度不足单独提示；已保存 Key 不等于连接验证成功，更改服务设置后清除旧验证标记。
- 未变化的资料复用索引，批量导入后的内容解析在后台进行；原有引用和无依据提示继续保留。
- pypdf 锁定版本与最低版本更新为 6.18.1，避免继续从旧 6.15.0 构建。

## 如何体验

1. 单独启动并配置你的翻译程序（本次核对协议为 0.5.0 的 IPC-v1）。
2. 在译答设置中选择字幕来源 `translation-program`，保存。
3. 在翻译程序和 Windows 字幕中设置听取、译文语言；译答的回答语言独立设置。
4. 译答仍需自己的 AI 服务配置以生成建议，不读取翻译程序或 LCT 的 Key。
5. 当前上游仅支持一个订阅客户端；不要同时运行其他订阅器占用连接。
6. 如不能连接，退出其他订阅器、确认翻译程序正在运行，或手动切回
   `windows-captions` / `livecaptions-translator`。不会自动回退并额外产生 API 调用。

## 验证与边界

- 168 项本地测试通过，包含原有功能、Tk 界面、模拟协议、真实 Windows
  命名管道握手／断线重连、旧结果隔离、资料增量索引与余额错误分类。
- 静态检查、源码敏感信息扫描和依赖许可证检查通过。
- 测试只使用合成字幕；Windows 管道测试服务是独立测试夹具，不等于实际音频全链路验收。
- 连接实际翻译程序时检测为未运行／未连接，未宣称已完成其真实音频联动。
- 当前上游无可靠麦克风状态、动态语言列表或控制接口；译答不制造虚假的麦克风开关。
- 连续修订没有稳定间隔时可能延迟自动回复，可点击“回答这一句”。这不是完整会议记录保证。
- UI 保留当前产品的中英葡界面／回复选项，订阅原文语言标签不强制限制三语。
- 本地构建为未签名预览；不是锁定 Python 3.13 环境的可复现正式发行。
- 未覆盖已有安装，未读取或迁移私人资料，未上传 GitHub。
