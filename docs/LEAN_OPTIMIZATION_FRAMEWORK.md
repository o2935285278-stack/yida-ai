# Yida AI 瘦身优化框架

版本基线：0.2.5-beta（执行前重新核对版本和 git 状态）

本文只定义架构、边界、执行顺序和验收口径。重复性的文件迁移、字段替换、测试样例复制和批量重构由后续执行任务完成。

## 目标

1. 提供轻量默认安装包，减少不使用的兼容组件和跨平台资源。
2. 缩短启动到界面可操作的时间，把资料索引移到后台并保持状态可见。
3. 限制字幕、翻译、回答、资料索引和 UI 状态的生命周期，避免长时间运行增长。
4. 将主界面拆为清晰的职责边界，降低后续维护成本。
5. 保留 Windows 原生字幕、独立翻译程序、LCT 兼容源、DOCX/PDF/TXT/MD 资料导入和现有回答功能。

## 不变量

- 不删除用户资料、API Key、历史记录或现有配置。
- 不把 LCT 重新设为默认字幕源。
- 没有 LCT 时，原生字幕和 translation-program 仍能构建和运行。
- 同一字幕的修订、迟到翻译和 AI 结果必须更新原卡片，不得重复创建。
- 最新翻译保持在顶部；用户阅读历史时不抢滚动位置。
- 回答正文保持可直接使用，界面不显示“当前问题”。
- 所有 Tk 控件更新在主线程执行；后台任务有界、可取消、可恢复。
- 未实测的体积、速度和内存收益不得写成保证。

## 目标模块边界

```text
src/yida_ai/
├─ application.py             运行时装配、组件选择、生命周期总入口
├─ core/
│  ├─ controller.py            字幕事件到翻译/回答的状态流转
│  ├─ engine.py                有界请求队列、结果隔离、关闭流程
│  └─ models.py                事件、回答、资料引用等数据结构
├─ adapters/captions/         字幕来源和翻译接入，不负责 UI
├─ retrieval/
│  ├─ documents.py             文件解析、导入、缓存失效
│  └─ keyword.py               轻量索引和检索
├─ ui/
│  ├─ app.py                   主窗口装配与页面协调
│  ├─ timeline_view.py         翻译卡片、置顶排序、滚动跟随
│  ├─ import_view.py           资料选择、拖拽、进度和错误展示
│  └─ settings_view.py         设置、连接状态和启动状态
└─ services/
   ├─ task_manager.py          有界后台任务、取消、关闭和去重
   └─ index_service.py         后台资料索引、持久缓存、原子替换
```

以上为职责目标。迁移时优先抽取稳定边界，不要求一次性完成目录重排；保留兼容导入路径，避免大范围重复复制代码。

## 构建配置分层

### Lite

- 目标：原生 Windows 字幕、translation-program、翻译、回答、资料导入。
- 不附带 LCT 可执行文件和 LCT 专用运行资源。
- 只收集目标 Windows x64 的 tkinterdnd2 资源和实际 Tcl/Tk 资源。
- 缺少 LCT 时，选择 LCT 来源应显示可操作的组件缺失提示。

### Compatibility

- 目标：保留旧配置和 LCT 用户的兼容安装包。
- 附带经校验的 LCT 可执行文件、版本和哈希清单。
- 与 Lite 共用源码和测试，差异只存在于构建输入和安装器文件列表。

### BuildManifest

构建阶段输出清单，至少记录：版本、构建 Python、包类型、文件数量、未压缩目录大小、安装器大小、LCT 是否包含、SHA-256、签名状态和测试命令。

## 执行阶段

### Phase 0：基线

- 核对版本、未提交修改和当前构建来源。
- 记录 Lite/Compatibility 的体积、启动耗时、空闲/持续输入内存和线程数。
- 建立同一机器、同一数据集、同一输入脚本的比较方法。

### Phase 1：打包瘦身

- 统一 `YidaAI.spec` 与 `build_windows.ps1` 的资源入口。
- 移除 tkinterdnd2 的非 Windows 架构和无用 Tcl 变体。
- 把 LCT 从默认打包改为构建配置选项。
- 校验许可证、第三方声明和安装器清单与实际内容一致。

### Phase 2：资料索引生命周期

- 导入时复用解析结果，避免全文重复解析。
- 使用流式哈希，避免重复读取两个完整文件。
- 引入带文件签名、解析器版本和分块版本的持久缓存。
- 启动时后台加载索引，索引原子替换，删除文件时清除索引。

### Phase 3：资源生命周期

- 审核卡片、隐藏事件 ID、Text window、队列、定时回调和线程的上限。
- 为连接测试、资料导入、语言检测和回答重试做任务去重。
- 关闭、新会话、来源切换时取消或隔离旧任务。

### Phase 4：UI 拆分

- 先抽取 timeline/import/settings 的纯 UI 协议和回调接口。
- 保留 `YidaApp` 作为协调器，避免重复复制状态逻辑。
- 每次抽取后运行现有 GUI 和事件回归测试。

### Phase 5：构建验收

- 使用锁定的 Python 3.13 构建 Lite 和 Compatibility。
- 验证源码版、Lite、Compatibility 的启动和退出。
- 验证字幕来源、DOCX/PDF/TXT/MD 导入、置顶显示、直接回答和历史恢复。
- 连续合成输入至少 30 分钟，记录资源曲线；结果注明实测或未验证。

## 验收指标

| 项目 | 必须满足 |
|---|---|
| Lite 构建 | 无 LCT 文件仍可构建、安装、启动 |
| Compatibility | 旧 LCT 配置仍可使用，版本和哈希校验有效 |
| 资料 | DOCX 表格、文字 PDF、TXT、MD 可导入并可检索 |
| UI | 最新翻译置顶；旧卡片向下；回到最新可用 |
| 事件 | 修订、迟到翻译、迟到回答不重复建卡 |
| 生命周期 | 卡片、队列、线程、回调有界，退出可收敛 |
| 安全 | 构建包不包含私人配置、数据库、Key 或临时资料 |
| 报告 | 每个收益都有优化前后数据或明确标记未测 |

## 后续执行任务的输出格式

每完成一个 Phase，输出：

1. 根因和边界变化。
2. 修改文件和兼容性影响。
3. 测试命令及结果。
4. 优化前后体积/启动/内存数据。
5. 未验证项、风险和回滚方法。

不要把重复性的模块迁移、相同模式的测试复制和批量文案替换混入框架设计；这些属于后续执行阶段。
